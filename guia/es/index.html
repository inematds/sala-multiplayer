En resumen

Sala Multiplayer es un programa pequeño que corre en tu computadora y reúne en una sola conversación a ti (o a tu equipo), dos agentes de IA (Claude Code y Codex) y a quien escribe a tu bot de Telegram. Sirve para quien quiere trabajar con agentes junto con otras personas, o armar una atención al cliente en la que la IA redacta un borrador y un humano lo aprueba antes de que la respuesta salga. Los agentes corren con tu suscripción, sin API. Para usarla necesitas Node 24 y los CLI de Claude Code y de Codex instalados y con sesión iniciada.

Qué es

Una conversación, varios participantes

Primera versión práctica del concepto Multiplayer Agentic: en lugar de que cada persona hable sola con su IA, todos hablan en el mismo lugar.

👥 Personas y agentes juntos

Llama a @claude o @codex en la conversación. Los dos responden en la sala, con tu suscripción de Claude Code y de Codex.

📱 Telegram como puerta

Un solo bot recibe los mensajes. Los agentes responden por él con su nombre al frente ("Claude: ...").

✅ El humano al mando

En el modo atendimento (atención al cliente), la respuesta al cliente queda como borrador y solo sale cuando alguien del equipo la aprueba.

Cómo funciona

De Telegram al panel, con un freno en el medio

Todo mensaje entra a la sala, va a quien fue llamado y aparece en el panel al instante.

Mensaje (Telegram o panel)→ Ruta: @mención o valor por defecto del perfil→ Agente (Claude o Codex)→ Herramienta, si la pide→ Aprobación humana (atendimento)→ Respuesta en la sala y en Telegram

Dos perfiles listos

pessoa (personal): tú y tus agentes; el bot ignora a quien no es el dueño. atendimento (atención al cliente): los clientes escriben en Telegram, Claude atiende con la base de respuestas, Codex revisa cuando el equipo lo pide, y un supervisor o agente aprueba.

Herramientas

El agente la pide con una línea FERRAMENTA: nome | entrada y la sala la ejecuta. Ejemplos: base (base de respuestas), chamado, notas, hora.

Topes contra bucles

Hasta 4 turnos seguidos entre agentes (3 en atendimento) y un límite de respuestas por día (150 en el perfil pessoa, 300 en atendimento). Ambos evitan gastar la suscripción en vano.

Seguridad

El panel solo abre en esta máquina (127.0.0.1). El mensaje de otra persona se trata como dato, nunca como orden. Los agentes corren sin las herramientas propias del CLI, sin MCP y en una carpeta vacía.

Requisitos previos

Qué debe estar instalado

La demostración corre solo con Node. Para los agentes de verdad, los dos CLI deben tener la sesión iniciada en tu cuenta.

Node 24

La sala usa el SQLite que ya viene con Node (node:sqlite), sin dependencias que instalar.

# comprobar la versión
node --version   # v24 o más

Claude Code y Codex

Instalados y con sesión iniciada con tu suscripción. La sala llama a los dos CLI; no usa clave de API.

# los dos deben responder
claude --version
codex --version

Bot de Telegram (opcional)

Sin bot, la sala funciona solo por el panel. Con bot, necesitas el token de @BotFather.

# en Telegram
@BotFather → /newbot
Guía de uso · paso a paso

De la demostración al bot en línea

Empieza por la demostración, que usa agentes falsos y no gasta nada. Después activa los agentes de verdad y, al final, Telegram.

1

Descarga el proyecto

No hay npm install: el proyecto no tiene dependencias.

git clone https://github.com/inematds/sala-multiplayer
cd sala-multiplayer
2

Ejecuta la demostración

Abre el perfil atendimento con agentes falsos, para que veas las tres pantallas funcionando.

npm run demo   # abre http://127.0.0.1:4601
npm test       # 11 pruebas, sin llamar a agentes ni a Telegram
3

Activa los agentes de verdad

Elige el perfil. En el panel, escribe @claude o @codex para llamar a un agente.

npm run pessoa        # tú y tus agentes      → http://127.0.0.1:4600
npm run atendimento   # área de atención      → http://127.0.0.1:4600
4

Crea el bot en Telegram

En @BotFather, crea el bot y copia el token. Para que el bot lea mensajes en un grupo, desactiva la privacidad.

/newbot       # elige el nombre y copia el token
/setprivacy   # elige el bot → Disable
5

Completa el .env

El .env queda fuera de git. Averigua tu id numérico con @userinfobot. En atendimento, completa también los ids del supervisor y del agente.

cp .env.exemplo .env
# SALA_TELEGRAM_TOKEN=      token de @BotFather
# SALA_DONO_TELEGRAM_ID=    tu id
# SALA_SUPERVISOR_TELEGRAM_ID= / SALA_ATENDENTE_TELEGRAM_ID=  (atendimento)
6

Cada persona envía /start

Un bot de Telegram no puede iniciar la conversación. Sin el /start, no puede avisar de las aprobaciones. Después ejecuta el perfil de nuevo: el sello de Telegram en la parte superior del panel queda "ligado" (activo).

/start                # cada persona del equipo, una vez
npm run atendimento   # o npm run pessoa
7

Aprueba las respuestas

En atendimento, el borrador aparece en la parte superior del panel. Apruébalo ahí (puedes editarlo antes) o por Telegram.

/aprovar 3   # envía el borrador 3 al cliente
/recusar 3   # descarta el borrador 3
8

Crea tu propia área

Los perfiles en perfis/ definen quién participa, la personalidad de cada agente, las herramientas, la ruta por defecto, quién aprueba y los topes. Copia uno y ejecútalo con el nombre nuevo.

cp perfis/atendimento.json perfis/vendas.json
node server.mjs --perfil vendas
Pantallas

Las tres pantallas del panel

Todo se actualiza en vivo, sin recargar. Las pantallas caben sin desplazamiento de 360 a 1920 px de ancho.
