In short

Sala Multiplayer is a small program that runs on your computer and brings you (or your team), two AI agents (Claude Code and Codex), and whoever writes to your Telegram bot into one conversation. It is for people who want to work with agents alongside others, or set up a support desk where AI drafts a reply and a person approves it before it goes out. The agents run on your subscription, with no API. To use it, you need Node 24 and the Claude Code and Codex CLIs installed and logged in.

What it is

One conversation, many participants

First practical version of the Multiplayer Agentic concept: instead of each person talking to their own AI alone, everyone talks in the same place.

👥 People and agents together

Call @claude or @codex in the conversation. Both answer in the room, using your Claude Code and Codex subscriptions.

📱 Telegram as the door

A single bot receives the messages. The agents reply through it with their name in front ("Claude: ...").

✅ Human in control

In atendimento (support) mode, the reply to the customer becomes a draft and only goes out after someone on the team approves it.

🤖 Request a new agent

Ask, "create an agent to review my writing." Claude returns a proposal with estimated cost and time, and the agent joins only after the owner approves.

🧵 Topics with summaries

The conversation is grouped into topics in the right column. Click one to see a summary: what was decided, what is pending, who took part and how much it cost.

🔎 Visual flow and graph

Each message becomes a sequence diagram or a graph with numbered arrows: who called whom, in what order and how it ended. Beside it are the request, decisions and pending items.

How it works

From Telegram to the dashboard, with approval in the middle

Every message enters the room, goes to whoever was called and appears on the dashboard right away.

Message (Telegram or dashboard)→ Route: @mention or profile default→ Agent (Claude or Codex)→ Tool, if requested→ Human approval (atendimento)→ Reply in the room and on Telegram→ Topic updated

Two ready-made profiles

pessoa (personal): you and your agents; the bot ignores anyone who is not the owner. atendimento (support): customers write on Telegram, Claude answers using the answer base, Codex reviews when the team asks, and a supervisor or agent approves.

Tools

The agent asks with one line, FERRAMENTA: nome | entrada, and the room runs it. Examples: base (answer base), chamado (ticket), notas (notes), hora (time).

Who calls whom

Between agents, only an @id at the start of a sentence calls someone ("@codex, can you review this?"). Mentioning a name in the middle of a message does not call anyone. A reply that only confirms ("okay, I will wait for the Owner") calls no one and gets the "confirmation only" label. An agent calls someone back only if it asks them a question.

Limits to prevent loops

Up to 10 consecutive turns between agents (6 in atendimento), up to 12 agent replies per message across all branches (8 in atendimento), a daily limit (400 and 300), a limit per guest (30) and, if you want, per agent. The limit notice appears once per message.

Only the owner can make changes

Agent limits, model and effort, and guest rules are set on the Config screen with the owner password, or on Telegram with /config. Anyone else can ask in the chat, and the owner approves.

Security

The dashboard only opens on this machine (127.0.0.1). Messages from other people are treated as data, never as instructions. The agents run without the CLI tools, without MCP and in an empty folder.

Prerequisites

What needs to be installed

The demo runs on Node alone. For the real agents, both CLIs must be logged in to your account.

Node 24

The room uses the SQLite that ships with Node (node:sqlite), with no dependencies to install.

# check the version
node --version   # v24 or higher

Claude Code e Codex

Installed and logged in with your subscription. The room calls both CLIs; it does not use an API key.

# both must respond
claude --version
codex --version

Telegram bot (optional)

Without a bot, the room works through the dashboard only. With a bot, you need the token from @BotFather.

# on Telegram
@BotFather → /newbot
User guide · step by step

From the demo to a live bot

Start with the demo, which uses fake agents and costs nothing. Then turn on the real agents and, last, Telegram.

1

Download the project

There is no npm install: the project has no dependencies.

git clone https://github.com/inematds/sala-multiplayer
cd sala-multiplayer
2

Run the demo

It opens the atendimento profile with fake agents, so you can see four screens working: customers, a proposal for a new agent, topics and the visual flow. The demo starts fresh each time and does not touch the real room data.

npm run demo   # open http://127.0.0.1:4601
npm test       # 46 tests, no agents or Telegram called
3

Turn on the real agents

Pick the profile. In the dashboard, write @claude or @codex to call an agent.

npm run pessoa        # you and your agents   → http://127.0.0.1:4600
npm run atendimento   # support desk          → http://127.0.0.1:4600
4

Create the Telegram bot

In @BotFather, create the bot and copy the token. For the bot to read group messages, turn privacy off.

/newbot       # pick a name and copy the token
/setprivacy   # pick the bot → Disable
5

Fill in the .env

The .env stays out of git. Find your numeric id with @userinfobot. In atendimento, also fill in the supervisor and agent ids.

cp .env.exemplo .env
# SALA_TELEGRAM_TOKEN=      token from @BotFather
# SALA_DONO_TELEGRAM_ID=    your id
# SALA_SUPERVISOR_TELEGRAM_ID= / SALA_ATENDENTE_TELEGRAM_ID=  (atendimento)
6

Everyone sends /start

A Telegram bot cannot start a conversation. Without /start, it cannot notify people about approvals. Then run the profile again: the Telegram badge at the top of the dashboard shows "on".

/start                # each team member, once
npm run atendimento   # or npm run pessoa
7

Approve the replies

In atendimento, the draft appears at the top of the dashboard. Approve it there (you can edit it first) or on Telegram.

/aprovar 3   # sends draft 3 to the customer
/recusar 3   # discards draft 3
8

Invite someone on Telegram without asking for their ID

The person sends /entrar to the bot in a private chat. You receive the request on Telegram, and it also appears under "Pending approvals" on the dashboard (accepting it there requires the owner password). The guest can chat and call agents, but cannot approve anything or change settings, and has their own daily reply limit. To disable access, use /remover or the button on the Config screen.

/entrar        # the person, in the bot
/aceitar 7     # you: "Request 7: Ana (@ana) wants to join"
/recusar 7     # or reject
/remover ana   # disables access; they can leave with /sair
9

Request a new agent (and the topic organizer)

Write what you want in the room. Claude does not create anything on its own: it returns a proposal (name, role, engine, tools, daily limit) with cost and time per reply measured from previous replies. Without @topicos, the room groups messages into topics but does not write summaries. Once approved, each topic gets a summary, decisions and pending items, and each message uses one extra call from your subscription.

# in the room
@claude cria um agente que revise meus textos
@claude cria um agente que organize a conversa em tópicos   # id: topicos
/aprovar 4   # or on the dashboard, under Pending approvals
10

Adjust the limits

On the Config screen with the owner password (SALA_DONO_SENHA in .env), or on Telegram. Changes take effect right away.

/config                         # shows everything
/config teto_rodada 12           # agent replies per message
/config agente.claude.nivel super
11

Create your own desk

The profiles in perfis/ define who takes part, each agent’s personality, the tools, the default route, who approves and the limits. Copy one and run it with the new name.

cp perfis/atendimento.json perfis/vendas.json
node server.mjs --perfil vendas
